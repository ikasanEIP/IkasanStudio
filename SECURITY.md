# Security Policy

## Supported versions

Ikasan Studio is approaching its first formal Marketplace release. Security fixes are applied to the current `main` branch and to supported release branches when applicable. Older development snapshots and locally modified builds may not receive fixes.

## Reporting a vulnerability

Please do not disclose suspected vulnerabilities in a public GitHub issue, discussion, or pull request.

Use GitHub's private vulnerability reporting facility on the repository's **Security** tab when it is available. If private reporting is unavailable, email `david@davihilton.net` with the subject **Ikasan Studio security report**.

Include as much of the following as is safe to share:

- The affected Ikasan Studio version or commit
- IntelliJ IDEA edition and version
- Operating system and Java runtime
- A description of the vulnerability and its likely impact
- Reproduction steps or a minimal proof of concept
- Any suggested mitigation

Do not include real credentials, production payloads, private keys, or other sensitive customer data.

We will acknowledge a report as soon as practical, investigate it, and coordinate remediation and disclosure with the reporter. Please allow time for a fix to be prepared before publishing details.

## Scope

Security reports may concern the plugin, generated source code, bundled meta-packs, handling of project files or credentials, or interaction with IntelliJ Platform APIs. General bugs and feature requests should use the public issue templates instead.
